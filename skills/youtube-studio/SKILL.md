# 유튜브 작업실 (youtube-studio)

영상을 **만들기 전과 올리기 직전**에 필요한 글과 판단을 만든다. 모든 결과는 한국어로 쓴다.
**아무것도 직접 올리지 않는다.** 이 스킬은 쓰고, 올리는 건 사용자다. 모든 결과는 복사할 블록으로 끝내고,
마지막 줄은 항상 **"이대로 갈까요, 고칠까요?"** 로 묻는다.

## 0. 모드 판단

| 요청 | 모드 | 읽을 파일 |
|---|---|---|
| 대본, 훅, 오프닝, "뭐라고 말하지" | **대본·훅** | `references/script.md` |
| 제목, 썸네일 문구, 클릭률(CTR) | **제목·썸네일** | `references/package.md` |
| 자막(.srt)으로 컷 편집, NG·군말·공백 제거, 쇼츠 구간 찾기 | **편집·쇼츠** | `references/edit-shorts.md` |
| 시청 지속률, 이탈, "왜 안 끝까지 보지" | **지속률** | `references/retention.md` |
| 설명란, 태그, 검색 노출, 챕터(타임스탬프) | **검색·설명란** | `references/seo.md` |
| 댓글 답장, 고정 댓글 | **댓글** | `references/comment.md` |
| 이번 주·이번 달 뭘 올리지 | **업로드 계획** | `references/plan.md` |
| 채널 진단, "왜 안 크지" | **채널 진단** | `references/audit.md` |

여러 모드가 이어지면 순서대로 한다 (예: 바이럴 찾기 → 대본·훅 → 제목·썸네일).

## 1. 다른 스킬과 나누는 일 (겹치지 않게)

| 이런 요청은 | 여기로 넘긴다 |
|---|---|
| 특정 유튜브 링크를 보고 "왜 떴는지", 장면·편집·대본 뜯어보기, 스토리보드, 영상 생성 프롬프트 | **youtube-analyzer** (Gemini가 영상 화면을 직접 본다) |
| 쿠팡 파트너스 상품 쇼츠 제작·게시 | **coupang-affiliate-shorts** |
| 블로그 글 | 블로그 글 스킬 |

이 스킬에서 레퍼런스 영상의 구조가 필요하면 youtube-analyzer 결과를 받아서 쓴다. 같은 분석을 다시 하지 않는다.

## 2. 시작 전 공통 규칙

1. **말투 프로필**: 대본·제목·댓글은 사용자가 소리 내어 읽거나 사용자 이름으로 나간다. 아래 순서로 찾는다.
   ① 대화에 붙여 준 프로필 → ② `~/.claude/youtube/voice.md` → ③ 이 스킬의 `references/voice.md`.
   셋 다 비어 있으면 사용자 영상 세 개(링크나 자막)를 받아 말투를 추정하고, `references/voice.md` 형식으로 정리해 보여 준다.
2. **숫자를 지어내지 않는다.** 수치·결과·출처가 있으면 좋겠는데 없으면, 사용자에게 묻거나 숫자 없이 쓴다.
3. **투자 콘텐츠**(주식·코인·ETF 등): 수익 보장, 매수·매도 권유("지금 사세요"), 확정 표현("무조건 오릅니다")을 쓰지 않는다.
   조건부 시나리오("상단을 거래량과 함께 넘으면 …, 못 넘으면 …")로 쓰고, 설명란에 면책 문구를 넣는다.
4. **도구는 실제로 돌린다.** 훅과 제목은 눈대중으로 판단하지 않는다. 코드 실행이 안 되면 같은 규칙을 손으로 적용하고 "(스크립트 미실행)"이라고 표시한다.

## 3. 도구

모두 파이썬 표준 라이브러리만 쓴다. 한국어와 영어를 자동으로 판별한다.

```bash
python3 <이 스킬 폴더>/scripts/hookscore.py --hook "훅 한 줄"          # 훅 점수 (5항목 + 맞는 공식)
python3 <이 스킬 폴더>/scripts/hookscore.py hooks.txt                   # 여러 개 순위
python3 <이 스킬 폴더>/scripts/title.py --title "제목" --thumb "문구"    # 제목+썸네일 점검
python3 <이 스킬 폴더>/scripts/deadair.py transcript.srt                # 컷 편집 목록
python3 <이 스킬 폴더>/scripts/retention.py retention.csv --duration 600 --transcript transcript.srt
python3 <이 스킬 폴더>/scripts/swipe.py --rss @채널1 @채널2 --save c.json   # 아는 채널들 중 평소보다 터진 영상 (무료)
python3 <이 스킬 폴더>/scripts/swipe.py c.json --min 2.0
```

`scripts/hooks.json`: 훅 공식 21가지 (한국어 이름·모양·예시·실패 조건·판별 패턴).

**점수의 한계를 말한다.** hookscore 영어 규칙은 실제 훅 74개로 보정됐지만, 한국어 규칙은 같은 구조로 새로 만든 것이라
보정 데이터가 없다. 낮은 점수는 "다시 볼 이유", 높은 점수는 "약속이 아님"으로 전한다.

## 4. vidIQ 크레딧 쓰는 순서

vidIQ 무료 플랜은 크레딧이 적다 (월 약 150, 호출 대부분 5 → 한 달 약 30번). **효과가 큰 곳에만 쓰고, 나머지는 무료 도구로 한다.**

| 순위 | 일 | 방법 |
|---|---|---|
| ① 쓴다 | 바이럴 찾기 (모르는 채널까지 유튜브 전체 탐색) | `vidiq_outliers` 한 번에 넉넉히. 크레딧이 없으면 `swipe.py` (아는 채널만) |
| ② 아낀다 | 키워드, 지속률 데이터, 댓글 가져오기, 채널 분석 | 사용자가 준 자료(Studio CSV, 붙여 넣은 댓글)로 먼저. 자료를 못 줄 때만 vidIQ |
| ③ 안 쓴다 | 챕터, 제목 점수, 답글 생성 | Claude가 직접 (품질 차이가 거의 없음) |
| 허락 필요 | 클립 자동 생성 `vidiq_generate_clips` | 분당 과금. 사용자가 명시적으로 원할 때만 |

- vidIQ를 부르기 전에 `vidiq_balance`(무료)로 잔액을 확인하고, 이번 호출에 몇 크레딧이 드는지 한 줄로 알린다.
- 같은 질문으로 다시 부르지 않는다. 처음부터 `limit` 을 넉넉히 준다.
- vidIQ가 연결돼 있지 않으면 무료 경로만으로 끝까지 한다.
- 영상 장면 분석은 vidIQ가 아니라 **youtube-analyzer**(Gemini 무료 한도)가 맡는다.
