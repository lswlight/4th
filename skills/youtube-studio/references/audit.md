# 채널 진단 (원본: yt-audit)

문제 스무 개를 나열하는 진단은 중요한 하나를 피하는 방법이다. 이 진단은 **하나의 수정**으로 끝난다.

## 이 순서로 본다

1. **최근 제목 열 개를 한 묶음으로.** 채널 페이지처럼 목록으로 읽는다. 서로 다른 것을 약속하는가? 모두 `title.py` 로 돌린다. 제목이 전부 같은 모양이면 제목 문제가 아니라 포맷 문제다.
2. **썸네일을 피드 크기로.** 줄여서 본다. 무엇이 살아남나? 셋이 그 크기에서 안 읽히면 그게 수정 사항이고 나머지는 아직 중요하지 않다. vidIQ `vidiq_get_images` 로 썸네일을 받을 수 있다.
3. **최근 세 영상의 첫 15초.** 자막을 받아 `hookscore.py` 로 점수를 매긴다. 대부분의 채널이 여기서 잃는다.
4. **업로드 리듬.** 빈도가 아니라 **일정함**. 한 주에 여섯 개 올리고 한 달 쉬는 것보다 2주에 하나를 계속하는 게 낫다.
5. **지속률 모양** (지속률 모드).

vidIQ가 있으면: `vidiq_user_channels` 로 채널 확인 → `vidiq_channel_analytics`(report: top_videos, traffic_sources, shorts_vs_longform_split) → `vidiq_channel_videos` 로 최근 영상 목록. 2026-08-27부터 조회수 집계 방식이 바뀌었으니, 그 날짜 전후를 비교할 때는 `views` 대신 `engagedViews` 를 쓴다.

## 넘겨줄 것

- 가장 큰 수정 하나, 이름을 붙여서, 이번 주에 할 일과 함께.
- 이미 잘 되고 있는 것 셋 — 망가뜨리지 않도록. 구체적으로. "에너지가 좋아요"는 관찰이 아니다.
- 아직 하지 말 것과 이유.

마음에 없는 칭찬으로 시작하지 않고, 스무 개 목록으로 끝내지 않는다.
